# 1. Perception Token 到底是什么（直觉解释）

你定义的是：

```text id="p0"
T_perception = {
  feature: ViT embedding
  mask: segmentation mask
  track_id: temporal id
}
```

可以直接翻译成一句更工程化的话：

> **“带身份的视觉证据块（Evidence Chunk with Identity）”**

---

## 类比（非常重要）

它不是：

* ❌ pixel（像素）
* ❌ patch token（ViT token）
* ❌ object（对象）

而是：

| 类型               | 类比               |
| ---------------- | ---------------- |
| pixel            | 感知原子             |
| patch token      | 局部特征块            |
| perception token | “被标记 + 可追踪的语义证据” |

---

## 更直观理解：

一帧图像会被拆成：

```text id="p1"
“某个区域 + 某个语义 + 某个时间身份”
```

例如：

* “这辆车（mask）”
* “看起来是车（feature）”
* “第 12 帧的同一个车（track_id）”

---

# 2. 三个字段的本质意义

---

## 2.1 feature（DINO embedding）= “它是什么”

```text id="f0"
feature ∈ R^D
```

作用：

* 提供语义空间
* “像不像车 / 人 / 桌子”
* 不负责结构，只负责语义相似性

👉 本质：

> semantic prior（语义先验）

---

## 2.2 mask（SAM）= “它在哪里”

```text id="m0"
mask ∈ R^{H×W}
```

作用：

* 空间分割
* boundary definition（边界定义）

👉 本质：

> spatial grounding（空间锚定）

---

## 2.3 track_id（时间）= “它是谁”

```text id="t0"
track_id ∈ Z
```

作用：

* 跨帧一致性
* identity persistence（身份保持）

👉 本质：

> temporal continuity（时间连续性）

---

# 3. 三者合起来的本质（核心）

## Perception Token 的本质结构：

```text id="core"
T_p = (WHAT + WHERE + WHO)
```

| 维度    | 含义             |
| ----- | -------------- |
| WHAT  | feature（语义）    |
| WHERE | mask（空间）       |
| WHO   | track_id（时间身份） |

---

## 一句话总结：

> Perception Token = “带时间身份的语义分割证据”

### ❌ 问题3：没有 track_id → 时间崩坏
